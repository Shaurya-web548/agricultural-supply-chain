Agricultural Supply Chain Management System

A desktop application that follows produce from the farm to the customer. Farmers list crops, distributors buy wholesale, and customers order. Background threads check stock, update inventory and create shipments, with everything stored in MySQL.

Order workflow

What happens when a customer clicks “Place order”

The window stays responsive: the heavy work happens on OrderProcessingThread.

  1. 1Validate & save

    OrderService.placeOrder() checks every line, prices it from a HashMap product cache, and saves the order (PENDING), its items and a payment (PENDING).

  2. 2Hand off to a threadOrderProcessingThread

    A background thread starts and the UI returns immediately.

  3. 3Claim the order

    One conditional UPDATE moves it PENDING → PROCESSING, so the same order can never be processed twice.

  4. 4Reduce stock safely

    Each line runs quantity - ? WHERE quantity >= ?. If no row is updated, there isn't enough stock.

  5. 5Confirm

    The order becomes CONFIRMED, the payment PAID, and a shipment is created with a unique TRK- number.

  6. 6Ship & deliverShipmentTrackingThread

    The distributor (or the tracker thread) moves the shipment IN_TRANSIT → OUT_FOR_DELIVERY → DELIVERED, and the order follows: SHIPPED → DELIVERED.

  7. !If anything fails
    Not enough stock (InsufficientStockException) or a database error (DatabaseException): any stock already taken is returned, the order is CANCELLED and the payment FAILED. Nothing is left half-done.
Synchronization

Two buyers, one last sack of wheat

If two threads both read “10 left” and both sell 10, stock goes negative. That is a race condition, and three layers prevent it.

1

synchronized lock

Inside one program, only one thread changes stock at a time.

synchronized (INVENTORY_LOCK) {
  ... reduceStock ...
}
2

Conditional UPDATE

The check and the change happen in one SQL statement, so even two app windows (two separate JVMs) can't oversell.

UPDATE inventory
SET quantity_available =
    quantity_available - ?
WHERE product_id = ?
  AND quantity_available >= ?
3

Database CHECK

MySQL itself refuses a negative stock value: the final safety net.

CHECK (quantity_available >= 0)

Proven by a test

concurrentOrdersNeverOversell fires 10 orders of 15 units at the same instant with only 100 in stock. Exactly 6 are confirmed, 4 are cancelled, and stock ends at exactly 10.

Database design

Ten tables, normalised

Database agricultural_supply_chain. Foreign keys mean an order item can never point at a product that doesn't exist.

userslogin for every role; username & email UNIQUE
farmers1:1 with users; owns many products
distributors1:1 with users; licence UNIQUE
customers1:1 with users; places many orders
productsFK farmer; CHECK price > 0; ACTIVE / INACTIVE
inventory1:1 with product; CHECK quantity ≥ 0
ordersFK customer, optional distributor; status DEFAULT 'PENDING'
order_itemslinks orders ↔ products; stores the price at order time
shipments1:1 with order; tracking number UNIQUE
payments1:1 with order; PENDING → PAID / FAILED
users 1──1 farmers 1──∞ products 1──1 inventory
users 1──1 distributors 1──∞ orders            (optional link)
users 1──1 customers    1──∞ orders 1──∞ order_items ∞──1 products
                              orders 1──1 shipments
                              orders 1──1 payments

Run it

Run it on your own PC

Needs JDK 8, Maven 3.9 and MySQL 8. Full instructions are in the README.

  1. Get the code

    git clone https://github.com/Shaurya-web548/agricultural-supply-chain.git

  2. Create the database

    Run sql/schema.sql, sql/seed_data.sql and sql/app_user.sql in MySQL (choose your own password in app_user.sql first).

  3. Add credentials

    Copy db.properties.example to db.properties and enter that password.

  4. Build

    mvn package compiles the code, runs the tests and builds the jar.

  5. Launch

    run-app.bat opens the app window; run-applet.bat runs it as a real applet in appletviewer.
